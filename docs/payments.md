# Платежі: осколки за гроші

## Як це влаштовано

```
Магазин → «Купити 650 💎» → POST /api/shop/shards
  сервер: запис у журнал покупок (pending) → рахунок у monobank → pageUrl
гравець платить на сторінці monobank
monobank → POST /api/payments/mono/webhook (підпис ECDSA у X-Sign)
  сервер: перевіряє підпис → статус success → в одній транзакції
          покупка pending→paid і +650 осколків гравцю
гравець повертається на #/shop/paid/<id> → сторінка питає статус
  (і сам monobank, якщо повідомлення ще не дійшло) → «+650 💎»
```

- **Журнал покупок** (`purchases` у SQLite) — запис про кожну спробу: сума в копійках, валюта, статус
  (`pending`, `paid`, `failed`, `expired`, `refunded`), id рахунку в monobank. Запис з'являється до того,
  як гравця відправлено платити, тож жодна оплата не лишиться без сліду.
- **Рівно один раз.** Банк може надіслати повідомлення кілька разів, а гравець — оновити сторінку.
  Зарахування — це атомарний перехід `pending → paid` разом із додаванням осколків
  (`settlePurchase`): хто встиг першим, той зарахував, решта нічого не змінює.
- **Інша сума** (банк каже «оплачено 1 ₴» замість 199 ₴) ніколи не зараховується: покупка позначається
  як `failed`, у лозі з'являється рядок для ручної перевірки.
- **Повернення** (`reversed` у monobank) забирає осколки назад, навіть якщо баланс стане від'ємним.
- **Підпис.** Повідомлення без правильного підпису monobank (ключ береться з `/api/merchant/pubkey`)
  ігноруються. Якщо monobank змінить ключ, сервер раз перечитає його.
- **Шанси паків** показано в магазині під кожним паком: осколки купують паки з випадковими картками.
- Код: `src/economy/payments.ts` (набори, типи), `GameService.buyShards / applyPayment`,
  `server/monobank.ts`, тести — `src/economy/__tests__/payments.test.ts`.

## Ціни

`SHARD_PRODUCTS` у `src/economy/payments.ts` (у копійках): 120 💎 — 39 ₴, 650 — 199 ₴, 1400 — 399 ₴,
3000 — 799 ₴. Для порівняння: легендарний пак коштує 1000 💎, міфічний — 2500 💎.

## Перевірити локально (без грошей)

```bash
PAYMENTS=test npm start
```

У магазині з'явиться розділ «💎 Осколки» з позначкою «тестова оплата». Замість сторінки банку
відкривається екран із кнопками «Оплатити» / «Відхилити». У демо без сервера так само.
**Ніколи не вмикайте `PAYMENTS=test` на справжньому сервері:** там будь-хто «заплатить» кнопкою.

## Підключити monobank (Plata by mono)

1. **ФОП** з рахунком у monobank і групою, що дозволяє продаж цифрових товарів (уточніть у бухгалтера).
2. **Сайт для перевірки банком:** публічна оферта (`#/terms`), політика конфіденційності (`#/privacy`),
   ціни, контакти. Шаблони вже є — **заповніть дані ФОП** у `src/ui/LegalPage.tsx` (`SELLER`) і дату
   редакції. Шаблон не юридична консультація: перевірте його з юристом або бухгалтером.
3. **Заявка на інтернет-еквайринг** у кабінеті monobank для бізнесу (web.monobank.ua): адреса сайту
   `https://ultrachess.fly.dev` (або ваш домен).
4. **Тестовий токен** з того ж кабінету: рахунки створюються по-справжньому, але гроші не списуються.
   ```bash
   fly secrets set MONO_TOKEN=<тестовий токен> PUBLIC_URL=https://ultrachess.fly.dev
   ```
   `PUBLIC_URL` обов'язковий: за ним monobank надсилає повідомлення про оплату.
5. Купіть набір на сайті, перевірте: осколки прийшли, у адмін-панелі покупка «оплачено».
6. **Бойовий токен** замість тестового — і продаж відкрито.
7. **Фіскальні чеки (ПРРО).** Для ФОП, що приймає оплату карткою онлайн, зазвичай потрібні фіскальні чеки:
   monobank пропонує інтеграції з ПРРО (наприклад, Checkbox) у кабінеті. Уточніть зі своїм бухгалтером.

## Міжнародні платежі

monobank приймає картки Visa/Mastercard будь-якої країни, але рахунок у гривнях (банк гравця
сконвертує валюту). Якщо основна аудиторія буде за кордоном:

- **Stripe** — потрібна компанія в країні, де Stripe працює (наприклад, Польща чи Естонія); український ФОП не підходить.
- **Paddle / Lemon Squeezy** («merchant of record») — продають від свого імені й самі сплачують податки
  в країнах покупців; підтримку продавців з України перевірте в них напряму.

Новий сервіс — це ще один клас, що реалізує `PaymentProvider` (`createInvoice`, `status`) і перевіряє
підпис своїх повідомлень, як `server/monobank.ts`. Журнал покупок і зарахування лишаються тими самими.
