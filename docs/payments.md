# Платежі: уламки за гроші (Lemon Squeezy)

Уламки продає **Lemon Squeezy** — «Merchant of Record»: продаж іде від його імені, він приймає картки,
PayPal, Apple/Google Pay, сам нараховує й сплачує податки країни покупця (ПДВ, sales tax), видає чек і
переказує вам гроші за мінусом комісії (~5 % + $0.50). Тому для старту не потрібен ФОП: гроші накопичуються
на балансі Lemon Squeezy, а виплату ви отримуєте на банк чи PayPal. Отриманий дохід треба задекларувати
(деталі — з бухгалтером).

## Як це влаштовано

```
Магазин → «Купити 650 💎» → POST /api/shop/shards
  сервер: запис у журнал покупок (pending) → POST /v1/checkouts у Lemon Squeezy
          (наша ціна, наш id покупки в custom data) → посилання на оплату
гравець платить на сторінці Lemon Squeezy
Lemon Squeezy → POST /api/payments/lemon/webhook (HMAC-SHA256 тіла в X-Signature)
  сервер: перевіряє підпис → order_created зі статусом paid → в одній транзакції
          покупка pending→paid і +650 уламків гравцю
гравець повертається на #/shop/paid/<id> → сторінка чекає, поки покупка стане paid → «+650 💎»
```

- **Журнал покупок** (`purchases` у SQLite) — запис про кожну спробу: сума в центах, валюта, статус
  (`pending`, `paid`, `failed`, `expired`, `refunded`), id checkout у Lemon Squeezy. Запис з'являється до того,
  як гравця відправлено платити, тож жодна оплата не лишиться без сліду.
- **Рівно один раз.** Lemon Squeezy повторює повідомлення, поки не отримає 200, а гравець може оновити
  сторінку. Зарахування — атомарний перехід `pending → paid` разом із додаванням уламків
  (`settlePurchase`): хто встиг першим, той зарахував, решта нічого не змінює.
- **Ціна.** Її задає наш сервер у checkout (`custom_price`), покупець змінити її не може; податки
  Lemon Squeezy додає зверху. Тому сума в повідомленні не порівнюється (`amount: null`).
- **Повернення** (`order_refunded`, статус `refunded`) забирає уламки назад, навіть якщо баланс стане
  від'ємним. Часткове повернення уламків не забирає.
- **Підпис.** Повідомлення без правильного підпису (секрет вебхука) ігноруються з кодом 400.
- **Шанси паків** показано в магазині під кожним паком: уламки купують паки з випадковими картками.
- Код: `src/economy/payments.ts` (набори, типи, `PaymentProvider`), `GameService.buyShards / applyPayment`,
  `server/lemonsqueezy.ts`, тести — `src/economy/__tests__/payments.test.ts`.

## Ціни

`SHARD_PRODUCTS` у `src/economy/payments.ts` (у центах): 120 💎 — $0.99, 650 — $4.99, 1400 — $9.99,
3000 — $19.99. Для порівняння: легендарний пак коштує 1000 💎, міфічний — 2500 💎.

## Перевірити локально (без грошей)

```bash
PAYMENTS=test npm start
```

У магазині з'явиться розділ «💎 Уламки» з позначкою «тестова оплата». Замість сторінки оплати
відкривається екран із кнопками «Оплатити» / «Відхилити». У демо без сервера так само.
**Ніколи не вмикайте `PAYMENTS=test` на справжньому сервері:** там будь-хто «заплатить» кнопкою.

## Підключити Lemon Squeezy

1. **Акаунт** на lemonsqueezy.com, магазин (store) у **USD**. При активації магазину Lemon Squeezy
   перевіряє сайт: потрібні опис товару, ціни, умови продажу (`#/terms`) і політика конфіденційності
   (`#/privacy`) — сторінки вже є, **впишіть пошту для звернень і дату** в `src/ui/LegalPage.tsx` (`CONTACT`).
   Виплати: банк або PayPal (перевірте, що ваша країна є у списку для виплат).
2. **Товар** «Ultrachess Shards» з одним варіантом (ціна будь-яка, справжню ставить сервер). Запам'ятайте
   **Store ID** (Settings → Stores) і **Variant ID** (у товарі → варіант).
3. **API-ключ:** Settings → API → новий ключ.
4. **Вебхук:** Settings → Webhooks → URL `https://ultrachess.fly.dev/api/payments/lemon/webhook`,
   події `order_created` і `order_refunded`, придумайте **signing secret** (довгий випадковий рядок).
5. **Секрети на Fly:**
   ```bash
   fly secrets set LEMON_API_KEY=… LEMON_STORE_ID=… LEMON_VARIANT_ID=… LEMON_WEBHOOK_SECRET=… PUBLIC_URL=https://ultrachess.fly.dev
   ```
   Поки магазин у **test mode**, використовуйте тестовий API-ключ: оплата тестовою карткою
   `4242 4242 4242 4242` грошей не списує. Купіть набір на сайті, перевірте: уламки прийшли, в адмін-панелі
   покупка «оплачено».
6. Після активації магазину — бойовий API-ключ замість тестового, і продаж відкрито.

Інший сервіс (Paddle, Xsolla, monobank для ФОП — реалізація monobank є в історії git, коміт `e93d7fd`) —
це ще один клас, що реалізує `PaymentProvider` (`createInvoice`, `status`) і перевіряє підпис своїх
повідомлень, як `server/lemonsqueezy.ts`. Журнал покупок і зарахування лишаються тими самими.
