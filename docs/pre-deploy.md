# Аудит перед деплоєм

Що перевірено, що виправлено, що лишилось відомим обмеженням і що зробити перед публікацією.
Стан на жовтень 2026.

## Виправлено

**Безпека й чесність гри**

| Проблема | Як було | Як стало |
| --- | --- | --- |
| Гравець міг «зіграти за бота» | Наприкінці бот-партії клієнт надсилав ходи обох сторін. Сервер перевіряв лише легальність, тож бота можна було змусити програти й нафармити кубки або міфічну Комету | Клієнт надсилає тільки свої ходи (`POST /api/matches/:id/action`). Сервер сам рахує хід бота в окремому потоці (`server/botPool.ts`) і зберігає запис партії. Результат рахується з цього запису |
| Втеча з програної рейтингової партії | Закрив вкладку — і поразки не зараховано | Незавершена партія в лізі ботів чи у випробуванні продовжується з того самого місця, нова не починається |
| Загублена незавершена партія | Після 20 незакритих тренувань сервер не бачив відкриту рейтингову | Нове тренування закриває старі |
| Перебір паролів | Без обмежень | 10 спроб на пару «адреса + пошта» за 10 хв, ліміти на ходи й API (за сесією, тож уся група в одній Wi‑Fi не заважає одне одному) |
| Запити з чужих сайтів | Тільки `SameSite=Lax` | Додатково перевіряється `Origin` |
| Кривий JSON у запиті | `null` чи масив у тілі валили сервер (500) | Відповідь 400 з поясненням |
| Колода з клієнта | Невідомі поля зберігалися в базу, неправильні типи давали 500 | Колода збирається лише зі знайомих полів із перевіркою типів |
| Адмінська пошта в коді | Список можна змінити тільки в коді | Можна задати через `ADMIN_EMAILS` (див. чекліст) |
| Прихована інформація в партіях із людьми | Обидва клієнти отримували повний запис ходів: у DevTools було видно ілюзії, справжнього коня Міража й увімкнену Безсмертну | Кожен отримує лише свій вид партії (`src/engine/secure.ts`) і свої легальні ходи; версія — випадковий токен; прихована дія не породжує жодного повідомлення суперникові |
| Опитування кожні 1,5 с | Суперник дізнавався про хід із затримкою, сервер переграв партію на кожен запит | WebSocket (`/api/ws`): хід приходить за мілісекунди, перевірка `Origin` і сесії при підключенні, ліміт повідомлень |

**Продуктивність**

- Переграння партії зі 120 ходів займало 225 мс і блокувало сервер на кожному опитуванні.
  - Рушій тепер перевіряє хід, генеруючи ходи лише тієї фігури, що ходить. Перевірка кінця партії зупиняється на першому знайденому ході. Разом це дало 28 мс: у 8 разів швидше на сервері, у бота й на клієнті.
  - Сервер кешує останній стан кожної партії й догравати лише нові ходи. Список викликів більше не переграє завершені партії.
- Основний бандл зменшився з 491 до 424 КБ (gzip: 150 → 131 КБ). Екран гри й відео карток довантажуються, коли потрібні.
- Великі відповіді API стискаються gzip.
- Прихована вкладка не опитує сервер, а наздоганяє його, щойно її знову відкриють.
- Сервер запускається одним процесом Node (`node --import tsx`). Обгортка `npx tsx` тримала зайвий процес на ~50 МБ. На Fly.io задано 512 МБ, бо з одним потоком бота сервер займає ~160 МБ.

**Надійність**

- Обрив зв'язку в бот-партії: хід не губиться. Клієнт повторює запит із паузами, що ростуть (повтор безпечний), і показує «Немає зв'язку…».
- Партію з ботом можна продовжити після перезавантаження сторінки.
- Потоки бота самі перезапускаються. Якщо вони взагалі не можуть стартувати, бот рахує в основному потоці. Будь-який запасний хід потрапляє в лог (`Bot turn failed`), щоб не було тихого «тупого» бота.
- Прострочені сесії видаляються під час старту й раз на добу.

**Правила й тести**

- Затемнювач і Землетрус: текст картки казав «замість ходу». Насправді, і за рушієм, і за `engine-decisions.md`, кнопка хід не витрачає. Виправлено тексти, описи й відео.
- Фаз-тест рушія прогнано на 600 випадкових партіях по 200 дій без жодного збою. Знайдено й виправлено діру в самому тесті: хід, який можна зіграти лише через здібність.
- Додано тести: бот на сервері, неможливість обрати хід бота, продовження партії, закриття тренувань, перевірка колоди.
- Додано CI (`.github/workflows/ci.yml`): типи, тести й збірка на кожен push.

## Відомі обмеження

1. **Немає підтвердження пошти й відновлення пароля.** Адмін-акаунт займає той, хто першим зареєструється з адмінською поштою.
2. **Домовні перемоги між своїми акаунтами в лізі гравців.** Частково стримує денний ліміт паків. Можна заборонити повторні рейтингові бої з тим самим суперником протягом N хвилин.
3. **Один сервер і SQLite.** Горизонтально не масштабується, але для курсового проєкту з запасом. Бот на 1 vCPU обслуговує партії по черзі. Якщо гравців багато, допоможе `BOT_TIME_SCALE=0.6`.
4. **Перший запит після рестарту** переграє партії з нуля (кеш порожній). Це помітно лише на дуже довгих партіях.
5. **Міраж і шах:** якщо справжній кінь Міража оголосив шах, суперник це бачить (див. `engine-decisions.md`).

## Чекліст деплою (Fly.io)

1. Локально: `npm run typecheck && npm test && npm run build`. Те саме перевірить CI.
2. `fly launch --copy-config --no-deploy` (назва застосунку з `fly.toml` має бути вільна).
3. `fly volumes create ultrachess_data --size 1 --region waw`: база житиме в `/data`.
4. За бажанням `fly secrets set ADMIN_EMAILS=ваша@пошта`. Так пошту адміна не видно в репозиторії.
5. `fly deploy`. Перевірити `https://<app>.fly.dev/api/health` → `{"ok":true}`.
6. **Одразу** зареєструватися з адмінською поштою, ще до того як ділитися посиланням.
7. Прогнати сценарій руками:
   - реєстрація → стартовий пак → бій із ботом;
   - перезавантажити сторінку посеред партії: партія має продовжитись;
   - вимкнути Wi‑Fi посеред ходу й увімкнути знову;
   - другий пристрій: виклик другу та ліга гравців; у DevTools → Network → WS видно `/api/ws` і
     повідомлення `game` після кожного ходу;
   - третій пристрій відкриває посилання «Поділитися» з партії: глядач бачить ходи наживо, гравці — 👁 1.
8. `fly logs`: не має бути `Bot worker failed` чи `Bot turn failed`.
9. Резервні копії: Fly робить знімки тому щодня й тримає 5 днів. Вручну: `fly ssh sftp get /data/ultrachess.db`.
10. У день захисту поставити `min_machines_running = 1` у `fly.toml`. Інакше перший запит після простою будить машину кілька секунд.

- Навчальна перша партія: підказки «натисни фігуру → фіолетові клітинки — це її фішка».

- Відновлення пароля й підтвердження пошти (потрібен поштовий сервіс).
- Сезони в лізі гравців (скидання кубків і нагорода за місце).
- Журнал помилок клієнта (хоча б `window.onerror` → `POST /api/log`), щоб бачити збої в гравців.
- E2E-тест у CI (Playwright уже є в середовищі): реєстрація → пак → партія з ботом.
